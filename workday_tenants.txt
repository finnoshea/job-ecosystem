# Workday tenants to scrape, one site per line.
#
# Workday's public job API is per-tenant AND per-site, so unlike Ashby a single
# company name is not enough. Each line needs three parts:
#
#   host  tenant  site  [Display Name]
#
# WHERE THE PARTS COME FROM
#
# Start from a company's careers URL in a browser, e.g.
#
#   https://nvidia.wd5.myworkdayjobs.com/NVIDIAExternalCareerSite/job/...
#           A       B                        C
#
#   host   = A + B   ->  nvidia.wd5
#                         {company subdomain}.{workday shard}.myworkdayjobs.com
#                         The shard (wd1, wd3, wd5, wd12, ...) is assigned by
#                         Workday and cannot be guessed -- read it off the URL.
#   site   = C       ->  NVIDIAExternalCareerSite
#                         The first path segment. Case does not matter to the
#                         API (verified across several tenants), but copy it as
#                         shown so the file stays readable.
#
#   tenant           ->  nvidia
#                         NOT visible in the careers URL. It appears only in the
#                         API endpoint, which the browser does not show:
#
#   https://nvidia.wd5.myworkdayjobs.com/wday/cxs/nvidia/NVIDIAExternalCareerSite/jobs
#                                                 ^^^^^^ tenant
#
# In practice the tenant is almost always the same as the company subdomain
# (A above), so GUESS IT AND TRY IT. A wrong tenant fails immediately and
# loudly -- an error object or HTTP 400/404, never a silent empty list -- so
# trial is quicker than looking anything up:
#
#   curl -sX POST "https://{host}.myworkdayjobs.com/wday/cxs/{tenant}/{site}/jobs" \
#     -H 'Content-Type: application/json' \
#     -d '{"appliedFacets":{},"limit":20,"offset":0,"searchText":""}' | head -c 200
#
# If only the tenant is uncertain, this differs from the subdomain in rare
# cases. Fallbacks if the guess fails:
#
#   * DevTools -> Network, filter for 'cxs', then interact with the page
#     (search, paginate, open a job). The log shows the RESOLVED url that went
#     over the wire. Do not look at the page source or the request-builder code:
#     it is usually built from a variable (e.g. `/wday/cxs/${tenant}/...`), which
#     tells you nothing. You need a request that was actually sent, so reload
#     with the Network tab already open if nothing appears.
#   * The site's sitemap, referenced from robots.txt, lists job URLs that
#     include the /wday/cxs/ path.
#
# FINDING THE SITE NAMES
#
# A host on its own returns HTTP 406, and site names are not derivable from the
# company. Read
#
#   https://{host}.myworkdayjobs.com/robots.txt
#
# which lists every site the tenant exposes in its Sitemap lines. Or copy the
# segment straight out of the careers URL.
#
# A tenant may expose several sites -- Salesforce has nine -- and each needs its
# own line. Sites with zero openings are harmless but noisy; delete lines you do
# not care about. Some tenants list sites in robots.txt that they exclude from
# crawling; those are commented out below rather than enabled.
#
# Blank lines are ignored. A line starting with '#' is a comment. That a site
# exists does not mean it is large: Futureforce_Internships has 16 openings.
#
# Current sizes, for reference: Nvidia 2000, Salesforce 1524, ASMLPrivate1 191,
# Disney 609.
